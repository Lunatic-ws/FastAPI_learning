# 09 响应更改状态码

## 学习目标

- 掌握在路径操作函数内部动态修改响应状态码
- 理解装饰器默认值与运行时修改的优先级关系

## 核心概念

### 1. 运行时修改状态码

在路径操作中声明 `Response` 参数并直接设置 `status_code`：

```python
from fastapi import FastAPI, Response, status

app = FastAPI()

tasks = {"foo": "Listen to the Bar Fighters"}

@app.put("/get-or-create-task/{task_id}", status_code=200)
def get_or_create_task(task_id: str, response: Response):
    if task_id not in tasks:
        tasks[task_id] = "This didn't exist before"
        response.status_code = status.HTTP_201_CREATED
    return tasks[task_id]
```

- 装饰器里的 `status_code=200` 是**默认值**
- 函数内 `response.status_code = 201` 是**运行时值**，会覆盖默认值
- 典型场景：`PUT` 语义——资源已存在返回 200，新建了资源返回 201 Created

### 2. 优先级规则

```
运行时 response.status_code（最高）
    > 直接返回 Response 对象携带的状态码
        > 装饰器 status_code（最低/默认）
```

### 3. 与直接返回 Response 的对比

```python
# 方式二：直接构造响应对象
from fastapi.responses import JSONResponse

@app.put("/direct/{task_id}")
def direct(task_id: str):
    if task_id not in tasks:
        tasks[task_id] = "new"
        return JSONResponse(content=tasks[task_id], status_code=201)
    return JSONResponse(content=tasks[task_id], status_code=200)
```

- 注入 `Response` 参数方式可以继续返回普通字典/模型，代码更简洁
- 直接构造 Response 则需要自己处理内容序列化

## 最佳实践

1. **装饰器里写最常见情况的状态码**：文档中展示的默认值要与多数请求实际返回一致
2. **语义化状态码**：创建成功 201、无内容 204、不可重试的业务失败 422/400
3. **修改状态码同时记得改文档**：如需在 OpenAPI 中声明多个可能的状态码，配合 `responses` 参数

## 常见问题

**Q: return 字典后 response.status_code 还生效吗？**
A: 生效。FastAPI 先渲染你返回的内容，再把 Cookie/Headers/状态码合并进最终响应

**Q: raise HTTPException 能改状态码吗？**
A: 能，错误场景直接 `raise HTTPException(status_code=...)` 更符合习惯；本页方法适合"成功路径上不同结果不同状态码"的场景
