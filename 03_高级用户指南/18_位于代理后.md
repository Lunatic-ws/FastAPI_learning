# 18 位于代理后

## 学习目标

- 理解应用在反向代理（Nginx/Traefik 等）后面时的路径问题
- 掌握 `--root-path` 与 `root_path` 参数的使用

## 核心概念

### 1. 问题场景

应用在服务器上监听 `http://127.0.0.1:8000`，代理（如 Nginx）把它暴露在 `https://example.com/api` 下。此时：

- 代理把 `/api/items` 转发为 `/items` 给应用
- 应用不知道自己在 `/api` 前缀下，`/docs` 生成的接口地址、重定向 URL 都会错

### 2. 使用 root-path

启动时告诉应用它对外的前缀：

```bash
fastapi run main.py --root-path /api
# 或 uvicorn main:app --root-path /api
```

或在代码中：

```python
app = FastAPI(root_path="/api", root_path_in_servers=False)
```

效果：

- `/docs` 页面生成的请求路径自动变为 `/api/items`（由浏览器直接发往代理）
- OpenAPI 的 `servers` 字段自动填入 `root_path`
- **注意**：应用本身仍监听 `/items`（不带前缀），前缀转换由代理完成；`/docs` 路径本身也仍是不带前缀的 `/docs`（由代理转发）

### 3. 代理配置示例（Nginx）

```nginx
location /api {
    proxy_pass http://127.0.0.1:8000;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

### 4. 获取真实客户端 IP

代理转发后应用看到的来源地址是代理的 IP。需要读转发头：

```python
from fastapi import Request

@app.get("/ip")
async def get_ip(request: Request):
    forwarded_for = request.headers.get("x-forwarded-for")
    return {"client_ip": forwarded_for}  # 信任该头的前提：确认只有可信代理能设置它
```

- `X-Forwarded-For`：客户端原始 IP 链
- `X-Forwarded-Proto`：原始协议（http/https），用于正确生成 HTTPS 链接

### 5. 移除根路径

应用自己也在 `root_path` 前缀下被直接访问（无代理）时，可使用 `root_path_in_servers=False` 等配置调整 OpenAPI `servers` 展示，避免文档地址重复拼接前缀。

## 最佳实践

1. **root_path 只影响文档/URL 生成**：它不做任何前缀剥离，路径转换永远是代理的事
2. **只信任可信代理的转发头**：不要对任意来源的 `X-Forwarded-For` 直接当客户端 IP 用
3. **HTTPS 由代理终结**：应用侧配合 `--proxy-headers`（uvicorn）正确识别协议

## 常见问题

**Q: 打开 /api/docs 返回 404？**
A: 检查代理是否把 `/api/docs` 转发到应用的 `/docs`；root_path 不会让应用响应带前缀的路径

**Q: Swagger Try it out 请求 404？**
A: 大概率是 root_path 没设置，文档生成的请求地址缺了 `/api` 前缀，浏览器直接打到了代理上不存在的路径
