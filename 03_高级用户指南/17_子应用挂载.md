# 17 子应用挂载

## 学习目标

- 掌握用 `mount` 挂载子应用
- 理解主应用与子应用各自独立的文档和配置

## 核心概念

### 1. 挂载 FastAPI 子应用

```python
from fastapi import FastAPI

app = FastAPI()

subapp = FastAPI()

@app.get("/app")
async def read_main():
    return {"message": "Hello World from main app"}

@subapp.get("/sub")
async def read_sub():
    return {"message": "Hello World from sub application"}

app.mount("/subapi", subapp)
```

- 访问 `/subapi/sub` 由 `subapp` 处理
- 主应用与子应用是**完全独立**的 FastAPI 实例：各自的中间件、依赖、异常处理器互不影响

### 2. 独立的文档 UI

| 应用 | 文档地址 | OpenAPI JSON |
|------|----------|--------------|
| 主应用 | `/docs` | `/openapi.json` |
| 子应用 | `/subapi/docs` | `/subapi/openapi.json` |

子应用在 `/docs` 的文档中，其接口路径会自动带上 `/subapi` 前缀。

### 3. 挂载顺序很重要

`mount` 会接管该路径前缀下的**所有**请求（包括文档、静态资源）。必须保证挂载路径不会覆盖已有 API 路由；`StaticFiles` 等通配挂载应放在所有路由定义**之后**：

```python
app.include_router(api_router)          # 先注册 API 路由
app.mount("/static", StaticFiles(...))  # 通配挂载放最后
```

### 4. 典型场景

- **微服务拆分前的模块隔离**：大项目按业务域拆成多个子应用
- **不同 OpenAPI 文档分组**：管理后台 `/admin/docs` 与用户 API `/docs` 分开
- **挂载其他 ASGI 应用**：静态文件、另一个框架的应用

## 最佳实践

1. **能用 APIRouter 就不用子应用**：子应用是独立实例，代价是重复的应用级配置；多数场景 `include_router(prefix=...)` 就够了
2. **通配挂载永远放最后**
3. **版本化可用子应用**：`/v1`、`/v2` 各挂一个 FastAPI 实例，配置完全隔离

## 常见问题

**Q: 子应用的依赖注入/中间件和主应用共享吗？**
A: 不共享，各自独立。需要在两边都生效的中间件要分别添加

**Q: 挂载后 /subapi/docs 的"Try it out"能用吗？**
A: 能，子应用文档中的请求地址已自动带上前缀
