# 30 生成客户端

## 学习目标

- 理解基于 OpenAPI 自动生成前端/客户端代码的价值
- 掌握 openapi.json 的获取与常用生成工具

## 核心概念

### 1. 为什么生成客户端

FastAPI 自动生成的 OpenAPI 文档不只是给人看的——它是一份机器可读的接口契约。用生成工具可以直接产出带**类型**的客户端代码：

- 前端不用手写请求函数和数据结构
- 接口改了，重新生成即可，编译器立刻报出所有不兼容处
- 自动补全和类型检查全链路打通

### 2. 获取 openapi.json

FastAPI 默认在 `/openapi.json` 提供文档：

```bash
curl http://127.0.0.1:8000/openapi.json > openapi.json
```

### 3. 常用生成工具

| 工具 | 目标语言/场景 | 命令示例 |
|------|--------------|----------|
| **openapi-generator-cli** | TypeScript/Java/Python 等 50+ 语言 | `openapi-generator-cli generate -i openapi.json -g typescript-axios -o ./src/client` |
| **Hey API** | 前端 TS（现代、类型友好） | `npx @hey-api/openapi-ts -i openapi.json -o src/client` |
| **orval** | 前端 TS + React Query 等 | `npx orval --input openapi.json` |
| **openapi-python-client** | Python 客户端 | `openapi-python-client generate --url http://127.0.0.1:8000/openapi.json` |

### 4. 生成后的使用示例（TypeScript）

```typescript
// 生成的客户端自带类型
import { ItemsService } from "./src/client";

const item = await ItemsService.readItem({ itemId: 5 });
// item 的类型是 ItemPublic，改接口后此处编译报错
```

### 5. CI 中自动再生成

把生成命令放进 CI/脚本：每次后端接口变更，PR 中自动更新客户端代码，前端同事在 code review 时立刻看到接口差异。

```yaml
# GitHub Actions 示例片段
- run: npx @hey-api/openapi-ts -i ./openapi.json -o ./frontend/src/client
```

## 最佳实践

1. **提交生成的代码到仓库**（或用包管理分发）：保证前后端接口版本一致、可回溯
2. **用响应模型过滤字段**：OpenAPI 的 schema 只含 `response_model` 声明的字段，生成代码更精确
3. **为前端单独生成**：不同端（Web/小程序/移动端）可各自选择最适合的生成器与语言

## 常见问题

**Q: 生成代码很丑/依赖不想要怎么办？**
A: 换生成器（不同工具风格差异大）或用生成器的模板/配置定制输出

**Q: 生成代码和手写冲突？**
A: 约定生成目录独立（如 `src/client`，头部标注 DO NOT EDIT），禁止手改，全部走再生成
