# 01 流式数据

## 学习目标

- 掌握用 `yield` 实现流式响应（StreamingResponse）
- 理解流式传输与 JSON 序列化的区别
- 学会处理文件流与事件循环阻塞问题

## 核心概念

### 1. 声明 `response_class=StreamingResponse` 后用 `yield` 逐块发送

```python
from collections.abc import AsyncIterable, Iterable

from fastapi import FastAPI
from fastapi.responses import StreamingResponse

app = FastAPI()

@app.get("/story/stream", response_class=StreamingResponse)
async def stream_story() -> AsyncIterable[str]:
    for line in message.splitlines():
        yield line
```

- 路径操作函数改成生成器（有 `yield`），每个 `yield` 的数据块立即发送给客户端
- 也可以是普通 `def` 生成器（`Iterable[str]`），或 `bytes` 块（`yield line.encode("utf-8")`）
- FastAPI 会把每个数据块**原样**交给 `StreamingResponse`，不做 JSON 转换和序列化

### 2. 类型注解是可选的

```python
@app.get("/story/stream-no-annotation", response_class=StreamingResponse)
async def stream_story_no_annotation():
    for line in message.splitlines():
        yield line
```

流式场景下 FastAPI 不用 Pydantic 处理数据，注解只服务编辑器和工具。这同时意味着：按需精确生成与编码字节数据的**自由和责任**都在你手上。

### 3. 流式文件与阻塞问题

类文件对象默认不支持 `await`，读取磁盘/网络文件是阻塞操作：

```python
from io import BytesIO
from fastapi.responses import StreamingResponse

class PNGStreamingResponse(StreamingResponse):
    media_type = "image/png"

# 普通函数会在线程池中运行，不阻塞事件循环
@app.get("/image/stream-no-async", response_class=PNGStreamingResponse)
def stream_image_no_async() -> Iterable[bytes]:
    with read_image() as image_file:
        for chunk in image_file:
            yield chunk
```

- 阻塞读取时把函数声明为常规 `def`，FastAPI 会放到线程池执行
- `io.BytesIO` 是内存对象不会阻塞，是例外情况
- 迭代对象逐条 yield 时可用 `yield from image_file` 简写

### 4. 自定义 media_type

继承 `StreamingResponse` 设置 `media_type`（如 `image/png`），或直接传参：

```python
StreamingResponse(gen, media_type="text/plain")
```

## 最佳实践

1. **大文件/大数据必须流式**：不要把整个文件读进内存再返回
2. **阻塞 IO 用 `def`**：避免阻塞事件循环；需要混用阻塞与异步时可用 Asyncer（FastAPI 姐妹库）
3. **配合 SSE/JSON Lines**：逐行产出 JSON 字符串就是逐行流式协议的基础

## 常见问题

**Q: StreamingResponse 和直接返回 bytes 的区别？**
A: 直接返回会把全部数据一次性生成并放进内存再发送；流式边生成边发送，首字节延迟低、内存占用小

**Q: 什么时候不能流式？**
A: 需要设置 `Content-Length`（如断点续传、精确进度）或响应需要整体校验的场景
